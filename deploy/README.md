# Стенд: как развернуть проект на сервере

Схема: push в `main` → CI проверяет → job `publish` кладёт образы в ghcr.io → сервер раз в 2 минуты сам забирает новую версию (`pull.sh`).
Секреты в GitHub не нужны, SSH-доступ к серверу для деплоя не нужен.

## 1. Подготовить репозиторий

1. В `docker-compose.yml` у бэкенда и фронтенда указать `image: ghcr.io/<владелец>/<репозиторий>-backend:latest` (и `-frontend`) рядом с `build:`.
2. Порт фронтенда задать через переменную: `ports: ["${FRONT_PORT:-3000}:80"]`.
3. В `.github/workflows/ci.yml` добавить job `publish` (см. этот репозиторий).
4. Сделать push в `main` и убедиться, что в Actions прошли `stack` и `publish`.
5. В `deploy/pull.sh` и `deploy/cloud-init.yaml` заменить `Algashev1/tp-docker-ci-demo` на свой репозиторий.

## 2. Создать ВМ (Cloud.ru Evolution)

1. Группа безопасности: входящий TCP 80 с 0.0.0.0/0, исходящий - любой.
2. Виртуальные машины → Создать: Ubuntu 24.04, 1 vCPU / 2 ГБ, диск 15 ГБ.
3. Сеть: «Публичный IP», группы `SSH-access` и группа с портом 80.
4. Включить «Скрипт cloud_init», **удалить шаблон целиком** и вставить `deploy/cloud-init.yaml`
   (шаблон Cloud.ru с добавленными секциями сервер отклонял с ошибкой «Image has not valid cloud_init yaml»).
   Вставьте в файл свой публичный SSH-ключ и не добавляйте в него кириллицу.
5. Создать и подождать 10-15 минут: ВМ ставит Docker и запускает проект.
6. Открыть `http://<публичный IP>`.

## 3. Проверка и обслуживание

- Новая версия появляется на стенде через 2-4 минуты после зелёного CI в `main`.
- Лог деплоя на сервере: `/var/log/app-deploy.log` (по SSH: `ssh stand@<IP>`).
- Данные БД лежат в volume `pgdata` и переживают обновления.
- ВМ можно выключать между занятиями, чтобы экономить бонусы. Диск и публичный IP оплачиваются и у выключенной ВМ - уточните в тарифах Cloud.ru.
