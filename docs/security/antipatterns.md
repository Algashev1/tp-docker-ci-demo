# 7 типичных уязвимостей: ошибка и исправление

Для каждой: как выглядит ошибка, чем опасна, как сделано правильно в этом репозитории.
Код «как нельзя» приведён только для разбора - в рабочем приложении его нет.

---

## 1. Контроль доступа только на фронтенде (OWASP A01)

Самая частая ошибка студенческих проектов: кнопку «Удалить» прячут в интерфейсе и
считают, что данные защищены.

**Как нельзя.** Сервер не проверяет, кто обращается:

```python
@app.delete("/api/teams/{team_id}")   # нет проверки прав
def delete_team(team_id: int):
    ...
```

Тогда достаточно отправить запрос в обход интерфейса:

```bash
curl -X DELETE http://ВАШ-САЙТ/api/teams/1
# команда удалится, хотя в браузере кнопки не было
```

**Как правильно (так сделано у нас).** Права проверяет сервер на каждом изменяющем
запросе:

```python
@app.delete("/api/teams/{team_id}", dependencies=[Depends(require_auth)], status_code=204)
def delete_team(team_id: int):
    ...
```

Без входа тот же запрос вернёт `401`:

```bash
curl -i -X DELETE http://ВАШ-САЙТ/api/teams/1
# HTTP/1.1 401 Unauthorized
```

Правило: **скрытая кнопка - не защита. Запрет живёт на сервере.**

## 2. SQL-инъекция (OWASP A05)

**Как нельзя.** Значение подставлено в запрос строкой:

```python
name = request.json["name"]
conn.execute(f"INSERT INTO teams (name) VALUES ('{name}')")   # опасно
```

Имя `Команда'); DROP TABLE teams; --` выполнится как отдельная команда и удалит таблицу.

**Как правильно (так сделано у нас).** Значение передаётся отдельным параметром, БД
никогда не воспринимает его как код:

```python
conn.execute("INSERT INTO teams (name, project, members) VALUES (%s, %s, %s)",
             (team.name.strip(), team.project.strip(), team.members.strip()))
```

Проверено тестом `test_sql_injection_in_name_is_stored_literally`.

Правило: **значения - только через параметры (`%s`) или ORM, не через f-строку.**

## 3. XSS - чужой скрипт в вашей странице (OWASP A05)

Комментарии, отзывы, описания - любое поле, которое потом показывают другим.

**Как нельзя.** Текст вставляют в страницу как HTML:

```javascript
el.innerHTML = note.text;   // текст с <script> выполнится
```

Если в комментарии окажется HTML-тег с обработчиком события, браузер выполнит его как код
у каждого, кто откроет страницу, - от имени этого пользователя.

**Как правильно (так сделано у нас).** Перед вставкой текст экранируется:

```javascript
function esc(s) {
  return String(s ?? "").replace(/[&<>"']/g, c =>
    ({ "&":"&amp;", "<":"&lt;", ">":"&gt;", '"':"&quot;", "'":"&#39;" }[c]));
}
// ... esc(note.text) ...
```

API отдаёт текст как данные JSON (проверено `test_xss_payload_is_returned_as_data_not_executed`),
а фронтенд выводит его экранированным. Дополнительно заголовок `Content-Security-Policy`
в [nginx.conf](../../frontend/nginx.conf) запрещает посторонние скрипты.

Правило: **`innerHTML`, `v-html`, `dangerouslySetInnerHTML` - красный флаг.
Выводите текст как текст.**

## 4. Пароль открытым текстом (OWASP A07)

**Как нельзя.** Пароль хранят как есть или через устаревший MD5:

```python
conn.execute("INSERT INTO settings VALUES ('password', %s)", (password,))
```

Утечка БД - и все пароли известны.

**Как правильно (так сделано у нас).** Хранится соль и хеш pbkdf2, сам пароль не
сохраняется никогда:

```python
def hash_password(password, salt=None):
    salt = salt or secrets.token_hex(16)
    digest = hashlib.pbkdf2_hmac("sha256", password.encode(), bytes.fromhex(salt), 200_000)
    return f"{salt}${digest.hex()}"
```

При неверном пароле - задержка в 1 секунду, чтобы замедлить перебор. Проверено
`test_password_is_not_stored_in_plaintext`.

Правило: **пароль - только хеш (bcrypt/argon2/pbkdf2) средствами библиотеки.
Свой алгоритм не изобретаем.**

## 5. Секрет в репозитории (OWASP A02, A04)

**Как нельзя.** Ключ или пароль прямо в коде или в закоммиченном `.env`:

```python
API_KEY = "sk-live-9f3c...real"   # попадёт в историю git навсегда
```

Публичный репозиторий индексируется ботами за минуты.

**Как правильно (так сделано у нас).** Секреты - в переменных окружения, в репозитории
только `.env.example` с заглушкой, реальный `.env` в `.gitignore`. На стенде пароль БД
генерируется случайно при первом запуске.

Если секрет всё же утёк: **удалить из кода мало - ключ нужно сменить**, он уже в истории.

Правило: **секретов в git нет. Проверяется `gitleaks`.**

## 6. Внутренние сервисы наружу (OWASP A06)

**Как нельзя.** В `docker-compose.yml` наружу выставлены БД и бэкенд:

```yaml
db:
  ports: ["5432:5432"]     # БД доступна из интернета
backend:
  ports: ["8080:8080"]
```

**Как правильно (так сделано у нас).** Наружу смотрит только фронтенд. Бэкенд виден
другим контейнерам по внутренней сети (`expose`), БД - вообще не публикуется:

```yaml
backend:
  expose: ["8080"]         # только внутри сети compose
frontend:
  ports: ["${FRONT_PORT:-3000}:80"]
```

Правило: **наружу - только то, что действительно нужно. По умолчанию запрещено.**

---

## 7. Трейсбек и debug наружу (OWASP A06, A10)

**Как нельзя.** Включённый debug или вывод исключения показывает пользователю путь к
файлам, версии, кусок кода и структуру БД - подсказку для атаки.

**Как правильно.** Пользователю - понятное сообщение и статус-код, подробности - в логи
сервера. У нас ошибки возвращаются как `HTTPException` с коротким текстом, а `nginx`
отдаёт свои страницы без `server_tokens`.

Правило: **наружу - «что-то пошло не так» и код. Подробности - в лог, не на экран.**

## Коротко

| Уязвимость | Правило |
|------------|---------|
| Доступ | запрет на сервере, не в интерфейсе |
| SQL | параметры/ORM, не f-строки |
| XSS | выводить текст экранированным |
| Пароли | хеш библиотекой, не открытый текст |
| Секреты | не в git, при утечке - менять |
| Порты | наружу только нужное |
| Ошибки | подробности в лог, не на экран |
