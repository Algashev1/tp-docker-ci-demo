# Чек-лист аудита безопасности своего проекта

Пройдите командой по своему репозиторию. Каждый пункт с ответом «нет» заводите дефектом
в Сфера.Задачах с меткой «безопасность» и приоритетом.

## Секреты и конфигурация

1. [ ] В репозитории нет паролей, ключей API, `SECRET_KEY` (проверить `gitleaks`, в том числе историю).
2. [ ] Реальный `.env` в `.gitignore`, в репозитории только `.env.example` с заглушками.
3. [ ] Debug-режим выключен, пользователь не видит трейсбеков и путей к файлам.
4. [ ] Наружу открыт только фронтенд (или nginx). БД и внутренние сервисы не публикуются.

## Вход и права

5. [ ] Каждый изменяющий запрос (POST/PUT/PATCH/DELETE) проверяет права **на сервере**.
6. [ ] Пользователь не может получить или изменить чужие данные, подставив чужой id.
7. [ ] Пароли хранятся хешем через библиотеку (bcrypt/argon2/pbkdf2), не открытым текстом.
8. [ ] Сессия или токен: cookie `HttpOnly`, у JWT длинный случайный секрет не из кода.

## Ввод пользователя

9. [ ] К БД - только через ORM или параметры, без склейки строк и f-строк.
10. [ ] Текст пользователей выводится экранированным (нет `innerHTML`/`v-html`/`dangerouslySetInnerHTML` с чужими данными).
11. [ ] Валидация на сервере: длина, тип, диапазон (не только в форме).
12. [ ] Загрузка файлов: ограничены тип и размер, файл не исполняется.

## Зависимости и ИИ

13. [ ] `pip-audit` / `npm audit` без критичных находок (или есть задача на обновление).
14. [ ] Код от ИИ прошёл ревью человеком, в AGENTS.md есть раздел «Безопасность».

## Данные с чужих сайтов (если парсите или берёте API)

15. [ ] Чужой HTML не выводится как есть - через санитайзер (DOMPurify, bleach).
16. [ ] Ключи внешних API не попадают во фронтенд.

## Пункты для Definition of Done

- В коде и истории нет секретов.
- Права на изменение данных проверяются на сервере.
- Пользовательский текст выводится экранированным.
